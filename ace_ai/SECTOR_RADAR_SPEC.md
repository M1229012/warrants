# 族群雷達演算法規格書 v1（2026-09-21 定案）

> 目標：從「族群漲幅排行榜」升級成真正的「族群雷達」——**最強 ≠ 正在轉強**。
> 原始訊號是**類股指數本身的變化（Δ）**，名次只是結果，只當輔助小字。

## 全域規則（先於各章）

1. **兩套 universe 不得混用**
   - 官方類股雷達：MIS 官方類股指數 ＋ 官方／FinMind 產業成員
   - 細產業／概念族群（CPO、散熱、記憶體…）：CMoney／自建 roster
   - 不可拿概念族群去套官方類股指數的變化。
2. **開盤特殊模式**
   - 09:00–09:14：只能標「開盤觀察」，不得出現「明顯轉強／轉弱」
   - 09:15–09:29：可標「初步轉強／初步轉弱」，Δ 基準用當日第一張快照（文案寫「開盤以來」）
   - 09:30 起：正式使用 30 分鐘 Δ
3. **處置股**：必須接證交所／櫃買官方處置有價證券公告（每日 1 請求）。在接好之前，代表股卡片標「未排除處置股」，**不得用量價異常猜測**。
4. **盤中一律標示估算**：抽樣得到的廣度、中位漲幅都要標「代表股抽樣」，不得寫成全族群統計。
5. **命名**：盤中只查代表股 → 圖上寫「**代表股**」；盤後有全市場收盤 → 才可寫「族群領漲 TOP3」。

## 1. 三層架構與資料來源

| 層 | 做什麼 | 資料來源 | 成本 |
|---|---|---|---|
| **L1 偵測** | 全類股現在漲幅、30 分鐘前漲幅、Δ、名次 | 證交所 MIS 類股指數快照（每 5 分鐘 1 次，已有） | 1 請求／5 分鐘 |
| **L2 驗證** | 候選族群的代表股報價 → 廣度、抽樣中位漲幅、代表股 TOP3、量能 | 富果 `intraday/quote`；成員名單用 FinMind 產業別（已快取）；流動性分層用本地底庫 | ≤ 3 族群 × 10 檔＝30 quotes／5 分鐘（全域共用） |
| **L3 判定** | 三態分類、文案、訊號保存 | 純計算 ＋ 本地 SQLite | 0 |

背景資料（0 API）：`local_market_cache` 的 20 日平均成交金額／均量、昨日型態分數、日 K。

## 2. 候選族群門檻（L1）

依指令分流，**不同雷達選不同候選**：

| 指令 | 候選選法 |
|---|---|
| 強勢族群 | 當下類股指數漲幅前 3～5 |
| 弱勢族群 | 當下類股指數跌幅前 3～5 |
| **轉強族群** | Δ30m 位於全類股**前 10%** **且** Δ ≥ **+0.20 ppt** |
| **轉弱族群** | Δ30m 位於全類股**後 10%** **且** Δ ≤ **−0.20 ppt** |

- `Δ30m = 現在類股指數漲幅(%) − 30 分鐘前漲幅(%)`，單位 ppt。
- 相對門檻（分位數）＋絕對門檻（0.20 ppt）**兩者同時滿足**，避免市場死水時硬生一堆「轉強」。
- 0.20 ppt 為初始值，第 7 章的驗證統計累積後重新校正。
- 候選上限 3 個族群（成本控制）。
- 排除：「其他」「其他電子」「綜合」「電子工業」（總和型指數）。

## 3. 代表股分層抽樣（L2）

共用底層 `RepresentativeBasketManager(market, purpose, size)`：

- **選股條件**：普通股 `[1-9]\d{3}`；≥21 根日 K；近 20 日平均成交量 ≥ 500 張且平均成交金額 ≥ 5,000 萬；非處置股；資料完整。
- **分層**（依近 20 日**平均成交金額**，不是張數）：**高 4 檔／中 3 檔／一般 3 檔**，共 10 檔。
- 同層內取**近 20 日漲跌標準差較小**者，當「成交節奏感測器」而非「熱門股籃子」。
- **每月第一個交易日重算**，其餘時間名單固定（樣本結構不可每天變動）。
- 選股機制共用，但**族群雷達與盤中量能曲線的 basket 可以不同**（用途不同：代表產業 vs 代表市場節奏）。

## 4. 三態判定（L3）

先定義：
- `廣度 = 代表股上漲檔數 ÷ 有效代表股數`
- `集中度差值 = 類股指數漲幅 − 代表股中位漲幅`（ppt）

### 轉強

| 狀態 | 條件（全部滿足） |
|---|---|
| **明顯轉強** | 通過第 2 章候選門檻；廣度 ≥ 60%；代表股中位漲幅 > 0；≥2 檔代表股明顯轉強；集中度差值 < 0.8 ppt |
| **轉強觀察** | 通過候選門檻；廣度 50–60%；中位漲幅 > 0 |
| **指數強但未擴散** | 集中度差值 ≥ 0.8 ppt **且** 廣度 < 50% |

> 注意：整族群普漲、只是一兩檔特別強時，差值也可能 > 0.8 ppt，**必須同時廣度 < 50%** 才算未擴散。

### 轉弱
方向相反：Δ 在後 10% 且 ≤ −0.20 ppt；廣度（上漲比）≤ 40%／40–50%；差值 ≤ −0.8 ppt 且廣度 > 50% ＝「指數弱但個股未同步」。

### 輔助資訊（不參與判定）
- **量能**：有盤中量能估算時，檢查代表股是否量價配合，只寫在文案，不當門檻。
- **昨日型態分數中位數**：只決定標籤 **低檔轉強／強勢續強／弱勢反彈**，**不得**因昨日型態差而否決今天的轉強訊號。

## 5. 圖片欄位與文案

每張族群卡片固定欄位（由上而下）：

```
油電燃氣　+2.02%              ← 族群名 ＋ 目前類股指數漲幅
明顯轉強                       ← 三態標籤
近30分 +0.84 ppt ｜ 代表股上漲 7/10
代表股｜台塑化 +4.2%・台塑 +2.8%・南亞 +2.1%
多數代表股同步走強，漲勢具有一定擴散性     ← 一句白話判讀
排名 4 → 2                     ← 小字輔助，可省略
```

文案模板（依三態擇一，數字由程式帶入）：
- 明顯轉強：「多數代表股同步走強，漲勢具有一定擴散性」
- 轉強觀察：「排名與指數同步墊高，但上漲面尚未過半，先列觀察」
- 指數強但未擴散：「指數走強主要集中在少數代表股，族群擴散度不足」
- 轉弱：「代表股普遍回落，賣壓不只集中在個別股」
- 開盤模式：「開盤初期波動大，僅先列入觀察」

## 6. 成本、快取、single-flight、降級

- **快取 key**：`sector_verify:{market}:{sector_id}:{YYYYMMDD}:{HHMM_bucket}`（5 分鐘桶）
- **single-flight**：同一 key 只允許一個請求真正去抓富果，其餘等同一個 Future；**成功共用結果、失敗釋放 inflight**（避免死鎖與重複抓）。
- **成本上限**：L2 每 5 分鐘 ≤ 30 quotes；超過候選上限時依 Δ 大小截斷。
- **降級策略**：
  - 富果不可用／額度吃緊 → 只輸出 L1（指數層級），卡片標「僅指數層級，未驗證個股」
  - 成員名單取不到 → 跳過該族群，不猜測
  - 代表股有效檔數 < 6 → 不判三態，只列指數變化

## 7. 訊號保存與事後驗證

每次產生訊號就寫一筆（SQLite）：

| 欄位 | 說明 |
|---|---|
| ts / market / sector_id | 訊號時間與族群 |
| index_change_pct | 當時類股指數漲幅 |
| delta_30m | 當時 Δ30m |
| breadth_pct | 代表股上漲比 |
| sample_median_pct | 代表股中位漲幅 |
| concentration_gap | 集中度差值 |
| state | 明顯轉強／轉強觀察／指數強但未擴散／轉弱… |
| after_30m_change | +30 分鐘後類股漲跌變化（回填） |
| close_change | 收盤後相對訊號點的變化（回填） |

回填時機：+30 分鐘由背景 tick 回填；收盤後一次回填當日全部訊號。

統計輸出（`/ace 系統狀態` 或 log）：

```
📡 族群雷達驗證（近 60 日）
明顯轉強 86 次｜30 分鐘後續強 57 次（66.3%）｜平均後續 +0.42 ppt
收盤仍高於訊號點 52 次（60.5%）
廣度 ≥70%：成功率 74.1%｜廣度 50–60%：成功率 52.8%
集中度 <0.3ppt：71.2%｜≥0.8ppt：44.6%
```

**用途**：門檻（55%／60%／0.8 ppt／0.20 ppt）不永久寫死，累積樣本後用自己的歷史資料重新校正。

# v1.1 補充定義（實作前定案）

## 1. 「代表股明顯轉強」的定義
代表股同樣保留 30 分鐘前報價，計算 `stock_delta_30m = 現在漲幅% − 30分鐘前漲幅%`（ppt）。
- **明顯轉強**：`stock_delta_30m > +0.30 ppt`
- 「≥2 檔代表股明顯轉強」＝至少 2 檔符合上式（不是只看現在紅不紅）
- 09:30 前以當日基準快照計算，並沿用開盤模式的語氣限制

## 2. 訊號去重（signal episode）
- 同一族群同一狀態只在**第一次進入**時建立新事件；持續期間只更新既有事件（`last_seen`、極值）
- 離開該狀態後再進入，或距上次同狀態事件 **≥30 分鐘**，才可建立下一筆
- 第 7 章的成功率一律以 **episode** 為單位統計，不以每次 tick 計

## 3. 類股 ↔ 成員名單 mapping
- 建立固定對照 `official_sector_id -> {member_codes, source, updated_at}`，程式**不得靠名稱猜**
- `source` 值：`twse_official` / `finmind_proxy` / `manual`
- 使用 proxy 時 log 必須寫 `member_source=finmind_proxy`，卡片不顯示
- index universe 與 sample universe 必須來自同一個 mapping 版本

## 4. 當日基準快照（防重啟）
- 每日第一張快照**持久化**到 SQLite，重啟後沿用
- 基準快照時間 ≤ 09:05 → 文案「開盤以來」；晚於 09:05 → 文案「**自首次觀測以來**」，不得謊稱開盤
- 30 分鐘 Δ 的查找容錯：取「最接近 now−30 分鐘」且誤差 ≤ **8 分鐘**的快照；找不到才退回當日基準快照並改寫文案

## 5. 報價層 single-flight
除族群層 key 外，再加一層股票層：`quote:{market}:{stock_code}:{HHMM_bucket}`
→ 同一個 5 分鐘格內，同一檔股票只打一次 Fugle（族群成員重疊、其他功能共用時都適用）

## 6. 事後驗證「成功」定義
- 轉強訊號：`after_30m_change > 0` 判為續強；收盤 `close_change > 0` 判為收盤仍強
- 轉弱訊號：`< 0` 判為續弱
- **同時保存實際 ppt**，不只存布林值；統計時兩者都要輸出

## 工程約束（L2 實作時遵守）
- 走既有全域 Fugle rate limiter 與有限並發，**不可無限等待**
- 整個 L2 設 hard deadline；部分報價失敗但有效代表股 **≥6 檔** → 用部分結果並標記實際樣本數
- 有效代表股 **<6 檔** → 依規格降級（不判三態，只列指數變化）
- 任何情況下不得讓族群雷達拖住整個 Discord 回覆

# v1.2 族群雷達四欄位與判讀（2026-09-21 定案，含下方「v1.2 修正」）

> 固定看三件事：**強不強｜有沒有擴散｜有沒有量**。
> 名稱一律用「族群雷達」／「成交熱度」；**不得寫「資金流入／資金流向」**——成交金額有買有賣，
> 無法判斷淨流向。等未來接主動買賣（內外盤／逐筆方向）才可用「資金流向」。

## 1. 四個核心欄位

| 欄位 | 定義 | 資料 |
|---|---|---|
| 類股漲幅 | 官方類股指數漲跌幅 % | MIS 類股指數（現有） |
| Δ30m | 見第 2 章、v1.1 第 4 點 | 本地快照（現有） |
| 擴散度 | `上漲家數 / 有報價成員數`＋`成員中位漲幅` | MIS 成員批次報價，**全部上市成員**（不做流動性篩選） |
| 成交熱度 | `今日族群成交占比 ÷ 近 20 日族群成交占比中位數`，顯示為「1.8×」 | 見第 3 節 |

- 成員名單：`OfficialSectorMemberResolver`（`twse_official` 優先），index／sample universe 同源。
- 流動性門檻（均量 ≥500 張、均額 ≥5,000 萬）**只用在挑「領漲／領跌」個股**，不影響擴散度。
- 擴散度改用全部成員後，第 3 章的代表股 basket **不再用於族群雷達**（保留給盤中量能曲線日後遷移）。

## 2. 集中度與主要帶動股
- `集中度差值 = 類股漲幅 − 成員中位漲幅`（ppt）
- `主要帶動股`＝對類股指數貢獻最大的成員：`昨收市值 × 漲跌幅` 最大者（股數沿用 `index_contribution` 已存的已發行股數）；股數取不到時退回「成交金額最大的上漲股」並在 log 註明。
- 成分股 < 10 檔：卡片註明「成分股 N 檔」。

## 3. 成交熱度計算
- 盤中：`族群累計成交金額 ÷ 上市全市場累計成交金額`。
  - 分子分母是**同一時點的累計值**，時段曲線的放大倍數會互相抵銷，所以不必先估全天；等同「依曲線估全天後再算占比」，但少一層估算誤差。
  - 成員成交金額 ≈ MIS 累計量（張）× 1000 × 最新價（MIS 沒有逐檔成交金額，屬近似值）。
  - 分母來源待驗證：優先 MIS 大盤（`tse_t00.tw`）累計成交金額欄位；拿不到就不算成交熱度（不猜）。
- 基準：本地日 K 算近 20 個交易日每日 `族群成交金額 ÷ 上市全市場成交金額`，取中位數。0 API，每日算一次快取。
- 09:00–09:29 成交熱度標「初步」（早盤占比波動大）。

## 4. 判讀（上漲方向；下跌方向鏡像）

| 判讀 | 條件（全部滿足） |
|---|---|
| **全面走強** | 類股漲幅 > 0；廣度 ≥ 60%；中位漲幅 > 0；成交熱度 ≥ 1.2× |
| **集中拉抬** | 類股漲幅 > 0；集中度差值 ≥ 0.8 ppt **或** 廣度 < 50% |
| **有價無量** | 類股漲幅 > 0；廣度 ≥ 50%；中位漲幅 > 0；成交熱度 < 1.0× |
| （不標） | 其餘 |

- 下跌方向：全面走弱／集中下殺／無量下跌，門檻對稱（廣度改看下跌家數比）。
- 判讀優先序：集中拉抬 > 全面走強 > 有價無量。
- 開盤模式沿用：09:00–09:14 不標判讀，只列數據；09:15–09:29 判讀前加「初步」。
- 門檻（60%／50%／0.8 ppt／1.2×／1.0×）為初始值，第 7 章驗證統計累積後重新校正。

## 5. 畫面

```
族群雷達｜目前強勢 TOP3        ← 只收「非集中拉抬」者，依類股漲幅排序
  電子零組件 +3.28%
  近30分 +0.04 ppt ｜ 上漲 58/78 ｜ 中位 +1.65% ｜ 成交熱度 1.9×
  領漲 宏致 +9.74%・台達電 +8.07%
  全面走強：多數成分股同步走強，且成交熱度升溫

  集中型異動（小區塊，最多 2 列，取類股漲幅前 5 名中被判「集中拉抬」者）
  油電燃氣 +2.02%｜上漲 2/8｜主要由台塑化帶動

族群雷達｜近30分轉強 TOP3      ← 依 Δ 排序；每列同樣帶擴散度、成交熱度、判讀
族群雷達｜近30分轉弱 TOP3
```

- 頁首標題固定「族群雷達」，不沿用使用者問句裡的「資金流向」。
- 集中型異動用小字表格列，不佔大卡。

## 6. 成本
- MIS：類股指數 1 請求＋成員報價約 6～8 請求（9 族群 ≈ 300～400 檔，每請求 50 檔），同 5 分鐘桶共用；不佔富果額度。
- 20 日成交占比基準：本地計算，0 API。
- 整次成員報價 hard deadline 10 秒；逾時或失敗 → 只列指數層級，卡片標「未取得成分股資料」。

## v1.2 修正（定案，優先於上面第 3、4、6 節）

1. **集中拉抬改回 AND**：`類股漲幅 > 0 且 集中度差值 ≥ 0.8 ppt 且 廣度 < 50%`。
   普漲但權值股特別強（例：類股 +3.0%、中位 +1.9%、上漲 75%）不得判集中。
2. **成交熱度＝同時點比較**：`今日 HH:MM 族群成交占比 ÷ 過去交易日同一 5 分鐘桶族群成交占比中位數`。
   - 不可拿盤中占比去比日終全天占比（各產業成交節奏不同）。
   - 背景 tick 每 5 分鐘保存 `日期／sector_id／bucket／sector_turnover／market_turnover`。
   - 歷史有效日 < 5：只顯示「成交占比 x.x%」，不顯示倍數；≥ 5 日才顯示「成交熱度 1.43×」。
3. **成交熱度不可用時不得否決擴散**：廣度 ≥ 60% 且中位 > 0 → 標「廣泛走強」（熱度暫無資料），
   只是不能標「全面走強」。熱度介於 1.0～1.2× 也標「廣泛走強」。
4. **分母必須驗證**：MIS `tse_t00.tw` 的累計成交金額欄位與單位，先在 Railway 印出原始 payload 確認，
   以環境變數 `DISCORD_AI_RADAR_MARKET_TURNOVER_FIELD`／`_UNIT` 指定；未設定＝`market_turnover unavailable`，
   成交占比與熱度一律顯示「—」，不另造分母。
5. **成員報價完整率**：每批記 `requested／returned／missing`，缺的用小批重試一次；
   擴散度分母只用成功報價數並記 `coverage`；coverage < 80% → 不下任何判讀。
6. 最終判讀：全面走強／廣泛走強／集中拉抬／有價無量（下跌方向：全面走弱／廣泛走弱／集中下殺／無量下跌）。
